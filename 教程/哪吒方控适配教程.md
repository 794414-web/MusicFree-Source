# 哪吒方控适配教程

本文说明 Android 应用如何接收哪吒车机发送的方向盘媒体按键广播，并将它转换为上一首、下一首和播放/暂停操作。

## 一、工作原理

方向盘按键由车机系统识别后，发送一个普通广播：

- Action：`hozon.intent.action.SWC_MEDIA_KEY`
- 按键值：Intent extra `KeyEvent.keyCode`
- 按键值类型：`Int`，语义与 Android `KeyEvent` 的 key code 一致

广播只描述一次按键事件，不会替应用管理播放器状态。应用收到广播后，应先判断当前是否有可控制的媒体会话，再调用播放器或系统媒体控制接口。

常见按键值如下：

| Android 常量 | 数值 | 典型用途 |
| --- | ---: | --- |
| `KEYCODE_MEDIA_PREVIOUS` | 88 | 上一首 |
| `KEYCODE_MEDIA_NEXT` | 87 | 下一首 |
| `KEYCODE_MEDIA_PLAY_PAUSE` | 85 | 播放/暂停 |
| `KEYCODE_MEDIA_PLAY` | 126 | 播放 |
| `KEYCODE_MEDIA_PAUSE` | 127 | 暂停 |

不同车型、系统版本或按键配置可能只发送其中一部分值。不要仅凭按键文字猜测数值，应该在目标车机上记录实际收到的 `keyCode`。

## 二、动态注册广播

动态注册适合应用进程已经运行、并且只希望在播放器或页面活跃时接收方控的场景。下面的 Kotlin 示例将广播接收器封装成可启动和停止的控制器：

```kotlin
import android.content.BroadcastReceiver
import android.content.Context
import android.content.Intent
import android.content.IntentFilter
import android.os.Build
import android.view.KeyEvent

class SteeringWheelMediaController(
    context: Context,
    private val onMediaKey: (Int) -> Unit
) {
    private val appContext = context.applicationContext
    private var registered = false

    private val receiver = object : BroadcastReceiver() {
        override fun onReceive(context: Context, intent: Intent) {
            if (intent.action != ACTION_SWC_MEDIA_KEY) return

            val keyCode = intent.getIntExtra(EXTRA_KEY_CODE, KeyEvent.KEYCODE_UNKNOWN)
            if (keyCode != KeyEvent.KEYCODE_UNKNOWN) {
                onMediaKey(keyCode)
            }
        }
    }

    fun start() {
        if (registered) return

        val filter = IntentFilter(ACTION_SWC_MEDIA_KEY)
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU) {
            appContext.registerReceiver(receiver, filter, Context.RECEIVER_EXPORTED)
        } else {
            @Suppress("DEPRECATION")
            appContext.registerReceiver(receiver, filter)
        }
        registered = true
    }

    fun stop() {
        if (!registered) return
        appContext.unregisterReceiver(receiver)
        registered = false
    }

    private companion object {
        const val ACTION_SWC_MEDIA_KEY = "hozon.intent.action.SWC_MEDIA_KEY"
        const val EXTRA_KEY_CODE = "KeyEvent.keyCode"
    }
}
```

在 Activity 中可以按照页面生命周期使用：

```kotlin
private val steeringWheel = SteeringWheelMediaController(this) { keyCode ->
    when (keyCode) {
        KeyEvent.KEYCODE_MEDIA_PREVIOUS -> player.skipToPrevious()
        KeyEvent.KEYCODE_MEDIA_NEXT -> player.skipToNext()
        KeyEvent.KEYCODE_MEDIA_PLAY_PAUSE -> player.togglePlayPause()
        KeyEvent.KEYCODE_MEDIA_PLAY -> player.play()
        KeyEvent.KEYCODE_MEDIA_PAUSE -> player.pause()
    }
}

override fun onStart() {
    super.onStart()
    steeringWheel.start()
}

override fun onStop() {
    steeringWheel.stop()
    super.onStop()
}
```

如果应用需要在整个进程生命周期内响应方控，可以在 `Application` 或长期运行的播放器服务中注册，但必须保证进程结束或服务销毁前调用 `unregisterReceiver`。

## 三、将按键交给系统媒体会话

应用不是播放器本身时，不建议直接操作某个特定播放器。可以把方控事件转换成标准媒体按键，让当前活动的媒体会话处理：

```kotlin
import android.media.AudioManager
import android.view.KeyEvent

fun dispatchToActiveMediaSession(context: Context, keyCode: Int) {
    val now = System.currentTimeMillis()
    val down = KeyEvent(now, now, KeyEvent.ACTION_DOWN, keyCode, 0)
    val up = KeyEvent(now, now, KeyEvent.ACTION_UP, keyCode, 0)
    val audioManager = context.getSystemService(AudioManager::class.java)
    audioManager.dispatchMediaKeyEvent(down)
    audioManager.dispatchMediaKeyEvent(up)
}
```

在上述接收器中，可将 `onMediaKey` 替换为 `dispatchToActiveMediaSession(this, keyCode)`。如果应用拥有自己的 `MediaSession`，优先直接调用自己的 `TransportControls`，这样播放状态和焦点关系更容易维护。

## 四、最佳实践

1. 使用动态注册时，让注册和反注册严格成对，避免重复注册和 `ReceiverLeakedException`。
2. 在 `onReceive` 中只做解析和投递，不执行网络请求、数据库操作或长时间播放逻辑；耗时工作交给播放器线程或服务。
3. 使用 `getIntExtra` 的明确默认值，并忽略未知 key code。不要把缺少 extra 当成暂停。
4. 只处理 `KeyEvent` 常量，不要依赖裸数字。调试时可以同时记录 action、key code 和当前播放器状态。
5. 方控广播可能被多个应用接收。应用应通过媒体会话、音频焦点和前台状态决定是否响应，避免多个播放器同时切歌。
6. 不要假设广播一定携带“按下/抬起”字段。若目标系统提供 `KeyEvent.ACTION_DOWN` 之类的额外字段，先实测其语义，再做去重；没有确认前不要重复执行切歌。
7. 如果应用进程需要冷启动后也能响应，动态注册本身不够，需要由服务、前台媒体播放组件或车机允许的启动机制维持进程。

## 五、排查清单

- 确认应用实际注册了 `hozon.intent.action.SWC_MEDIA_KEY`。
- 记录收到的 `KeyEvent.keyCode`，不要只看方向盘图标。
- 检查应用是否有可用的 `MediaSession` 或播放器实例。
- 检查音频焦点、前台状态和播放器是否已释放。
- 确认 `start()` 与 `stop()` 的生命周期调用次数一致。
